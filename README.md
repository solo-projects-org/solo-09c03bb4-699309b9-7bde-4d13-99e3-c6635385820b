# 肿瘤变异位点比对

肿瘤变异数据员用于核对两家实验室（甲、乙）检测结果差异的网页工具。
一次上传**单条染色体的 FASTA 参考序列**和**甲、乙两份 VCF**，系统核对 REF、
归一化位点后列出**共有 / 甲独有 / 乙独有**位点及各自来源行号。

另附**变异注释**页面（导航栏"变异注释"或 `/annotate`）：上传单染色体 FASTA、
至多 200 条双等位 SNV 的 VCF 和 CDS TSV，判断每条 SNV 是否改变编码蛋白，
给出各命中转录本的原/新密码子、氨基酸与同义、错义、终止获得、终止丢失结论。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
```

打开 http://localhost:8000 。数据保存在名为 `vcf_data` 的卷里（`/data/vcf_compare.db`）。

### 本地开发

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
# 打开 http://127.0.0.1:8000
```

数据库路径可用环境变量 `DATABASE_PATH` 指定（默认 `./data/vcf_compare.db`）。

### 测试

```bash
pip install -r requirements-dev.txt
pytest tests/
```

`examples/` 目录有一组可直接上传的示例文件：

- 位点比对：`ref.fa` + `lab_a.vcf` / `lab_b.vcf`（另有一份含非法 REF 的
  `lab_bad.vcf` 用于演示失败）；
- 变异注释：`ann_ref.fa` + `ann_variants.vcf` + `ann_cds.tsv`（覆盖同义、错义、
  终止获得、终止丢失、CDS 外与同一 SNV 命中多个转录本的情形）。

## 比对规则

**记录合法性**（任一记录非法 → 整次比对失败，失败原因含文件与行号）：

- 每份 VCF 数据记录 ≤ 1000 条；染色体名须与 FASTA 序列名一致；
- POS 为正整数且不越出参考序列；REF 与参考序列逐碱基核对一致；
- 仅接受 A/C/G/T 的双等位 SNV 或纯插入缺失：REF≠ALT，ALT 不得为多等位（`,`）、
  符号型（`<DEL>`）、`*` 等；REF/ALT 含 N 或其他字符亦非法；
- 去除共有前后缀后两端都非空的记录（MNP、复杂替换）视为非法。

**归一化（等价写法归为同一位点）**：

1. 核对 REF 后，先去除 REF/ALT 的共有后缀、再去共有前缀；
2. 纯插入 / 纯缺失按参考序列**左对齐**（在串联重复、均聚物中滑到最左代表）；
3. 归一化后的 `(pos, ref, alt)` 为位点唯一键：插入的 `ref` 为空（表示在 pos 之前插入），
   缺失的 `alt` 为空，网页中以 `-` 显示。

**合并与归类**：同一文件内归一化键相同的记录合并为一个位点，保留全部原行号
（行号按上传文件的物理行计，含表头）；两份文件按键求交/差，分为共有、甲独有、乙独有。

## 变异注释规则

**输入**（任一输入非法 → 整次注释失败，不显示部分注释）：

- FASTA：与位点比对相同的单染色体参考序列；
- VCF：≤ 200 条记录，仅接受双等位 SNV（REF/ALT 各为一个 A/C/G/T 碱基），
  逐条核对 REF 与参考序列一致，完全相同的记录合并并保留全部行号；
- CDS TSV：每行 4 列 `转录本 ID、正负链(+/-)、起始、终止`（1 基闭区间，
  允许空行、`#` 注释行与一行表头）；≤ 5 个转录本，每个 ≤ 8 段；
  同一转录本须同向且区间互不重叠，区间须位于参考序列内；
  按转录方向拼接后的 CDS 只含 A/C/G/T 且总长为 3 的倍数。

**注释推演**：

1. 按转录方向拼接 CDS：正链按基因组坐标升序逐段取正链序列，
   负链按坐标降序逐段取反向互补序列（跨外显子的密码子自然落在拼接边界两侧）；
2. 对每条 SNV 找到其所在的全部转录本，按 CDS 内位置定位密码子，
   负链转录本上的 ALT 先取互补碱基再替换，得到原/新密码子；
3. 查标准遗传密码表得原/新氨基酸，结论分为：
   **同义**（含终止→终止）、**错义**、**终止获得**、**终止丢失**；
   未命中任何转录本的 SNV 标为 **CDS 外**；
4. 同一 SNV 命中多个转录本时，每个转录本在结果表中各占一行。

## 可靠性与并发

- 每次上传在一个事务内写入自己的报告与全部结果行（位点比对：`reports` / `variants` 表；
  变异注释：`annotation_reports` / `annotations` 表，均按报告 ID 关联），
  失败整体回滚，不留半成品；
- 非法记录只产生一条"失败"报告，**不改动任何旧报告**；
- 处理过程全部使用请求内的局部变量与每请求独立的数据库连接（WAL 模式），
  并发上传的报告不会混用不同批次的参考序列、位点和行号。

## 目录结构

```
app/
  compare.py    # FASTA/VCF 解析、REF 核对、左对齐归一化、集合比较（纯逻辑）
  annotate.py   # CDS TSV / SNV VCF 解析、密码子与氨基酸推演（纯逻辑）
  db.py         # SQLite 存取（WAL、单事务写入）
  main.py       # FastAPI 路由与页面渲染
  templates/    # 上传表单、报告列表、报告详情（比对 + 注释）
tests/          # 单元测试 + 网页集成测试 + 并发隔离测试
examples/       # 示例参考序列、VCF 与 CDS TSV
Dockerfile / docker-compose.yml
```
